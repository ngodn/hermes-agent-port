# custom_request_config.rs port notes

Ports the pure custom-provider `extra_body` selection from `agent/agent_init.py`
into `rust/crates/hermes-gateway/src/custom_request_config.rs`.

## What it covers

Three Python functions, all pure:

- `_normalized_custom_base_url` -> `normalized_base_url_str` / `_value`
- `_custom_provider_model_matches` -> `model_matches`
- `_custom_provider_extra_body_for_agent` -> `select_extra_body` (public API)

Public API:

```rust
pub fn select_extra_body(
    provider: &str, model: &str, base_url: &str, entries: &serde_json::Value,
) -> Option<serde_json::Map<String, serde_json::Value>>
```

## Scope boundary

The caller supplies `entries` already in the legacy list shape (one map per
provider, optional keys `provider_key` / `name` / `base_url` / `model` /
`models` / `extra_body`). Normalizing the v12+ unified `providers` config down
to that shape is a separate concern and stays with the caller. This module does
only the pure selection: it reads the values it is handed, copies the winning
`extra_body`, and never issues a request or infers a model.

## Preserved Python behaviour

- **Coercions.** `str(x or "")` collapses falsy values to `""` before `str`
  (`py_str_or_empty` on top of `truthy`). List catalog elements use a plain
  `str(m)` with no `or` guard (`py_str`). `str` and `repr` only diverge for the
  `str` type, so non-string arms reuse `python_value::python_repr`.
- **Strip.** `.strip()` uses `python_value::python_whitespace` (Unicode
  whitespace plus the four information separators), matching CPython.
- **Exact URL matching.** `strip()` then `rstrip("/")`, in that order, on both
  the target and each entry's `base_url`; a non-`str` entry url becomes `""`.
  The order is observable (see the `http://x/ /` edge test).
- **Named custom filter.** `custom` means no filter; `custom:<name>` matches an
  entry whose lowercased-stripped `provider_key` OR `name` equals the filter.
- **Model catalog priority.** A non-empty catalog hit returns first; then the
  `model`/`default_model` equality path; an entry with neither `model` nor a
  catalog matches everything.
- **First matching fallback.** Entries with a set `model` return their
  `extra_body` on a model match (short-circuiting the loop); entries with no
  `model` (including models-only entries) seed the fallback, first one wins.
- **Skips.** Non-dict entries, non-dict or empty `extra_body`, and URL
  mismatches are skipped, same as Python.

## Reused helpers

From `python_value.rs`: `truthy`, `python_repr`, `python_whitespace`. No new
scalar coercions were added.

## Tests

Inline `#[cfg(test)]` only. `matches_python_goldens` replays
`rust/tools/custom-request-goldens.json` (24 cases) through the public API.
Those goldens are generated by `rust/tools/gen_custom_request_goldens.py`, which
extracts the three real functions from `agent/agent_init.py` with `ast` and
execs just them (no agent-runtime import), so the fixture tracks the actual
source. Regenerate with:

```
mise x python@3.12.13 -- python rust/tools/gen_custom_request_goldens.py
```

Extra inline tests cover base-url normalization edges, non-array `entries`, and
the model-match-short-circuits-fallback ordering.
